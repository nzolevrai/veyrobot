## Modifications ciblées

- Prisma `7.10.0 → 7.10.1` (client, adapter PostgreSQL et CLI alignés) apporte `deepmerge-ts 8.0.2` et `mysql2 3.24.4`, tous deux hors plages signalées.
- `@veyrobot/db` aligne son Zod direct sur `4.6.7`, patch au-delà du seuil `4.6.6`.
- `discord.js` `14.27.0 → 14.28.1` conserve la majeure 14; son `undici ^6.27.0` est verrouillé sur le correctif `6.29.1`.
- Le graphe Fastify/Ajv accepte `fast-uri ^3` et `^4`, mais pnpm conserve les résolutions vulnérables du lockfile même après actualisation. Les overrides exacts `fast-uri@3.1.8 → 3.1.9`, `fast-uri@4.2.2 → 4.2.3` et `undici@6.29.0 → 6.29.1` sont compatibles avec les plages annoncées et limités aux versions vulnérables. Aucun override ne traverse une majeure.

## Vérifications et limites

Environnement local : Windows, Node `24.22.2` via `tools/pnpm.ps1`, pnpm `10.18.3`, PostgreSQL `17-alpine` et Redis `7-alpine` dans deux conteneurs jetables sans volume. Ils ont été supprimés après l’essai; les conteneurs et données de développement n’ont pas été démarrés ni modifiés.

- `tools/pnpm.ps1 install --frozen-lockfile` : réussi.
- `tools/pnpm.ps1 audit --prod --json` après modification : zéro vulnérabilité connue dans le registre interrogé; les résolutions réelles du lockfile sont `prisma 7.10.1`, `@prisma/client 7.10.1`, `@prisma/adapter-pg 7.10.1`, `deepmerge-ts 8.0.2`, `mysql2 3.24.4`, `zod 4.6.7`, `discord.js 14.28.1`, `undici 6.29.1`, `fast-uri 3.1.9` et `4.2.3`.
- `db:generate` : réussi avec Prisma Client 7.10.1. `db:migrate` : 14 migrations appliquées à la base isolée. La commande CI `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --exit-code`, exécutée depuis `packages/db`, a répondu `No difference detected`.
- `typecheck`, `lint` (dont les frontières et cycles), `build` : réussis; Next.js 16.4.5 et les applications API/bot ont compilé.
- `test` avec `RUN_POSTGRES_INTEGRATION=1`, `RUN_REDIS_INTEGRATION=1`, `RUN_DASHBOARD_ROUTE_INTEGRATION=1`, `RUN_DASHBOARD_BROWSER_INTEGRATION=1` : réussi. Résultats des suites Node : db 13, contracts 8, moderation 38, bot 10, dashboard 19; tests unitaires API 13. L’intégration API/Next Chromium construite a aussi réussi, avec OAuth/Discord simulés, PostgreSQL/Redis réels jetables et aucune mutation Discord réelle.
- Le parcours Firefox de l’intégration API a été tenté séparément mais ne s’est pas terminé localement : après environ deux minutes sans sortie, le processus d’intégration était encore actif et aucun processus Firefox n’était observable. Je l’ai interrompu; ce n’est pas enregistré comme un test réussi ni comme un défaut applicatif reproduit. Le job Firefox dédié de la CI reste la preuve attendue sur le SHA publié.
- Aucune connexion Gateway, sanction Discord ou déploiement public n’a été lancé. La construction/pression de toutes les images de production est réservée aux jobs CI de la branche; le build local du monorepo ne prétend pas la remplacer.

L’image Docker actuelle installe le workspace complet dans l’étape runtime; ces mises à niveau éliminent les versions signalées sans élargir cette intervention à la séparation des outils de migration et des images d’applications. L’audit ne couvre ni les vulnérabilités inconnues ni l’exploitabilité générale du produit.

Les autres constats en attente de la revue Claude restent inchangés et hors de cette tranche.
